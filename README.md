# The Brotosphere

The homing signal for all bros.

Give it a set of lifestyle preferences — enough bars, a golf course, a
reasonable drive to an NFL stadium, whatever — and it shows you which
parts of the country satisfy *all* of them. No rankings. No AI. No mystery
score out of 100. A hex is either green (meets everything you turned on)
or gray (doesn't).

**[Live demo →](#deploying-to-github-pages)** (once you've deployed it —
see below)

## What's in V1

- A national H3 hex grid, one static GeoJSON file, no backend
- 10 filterable categories: bars, breweries/distilleries, golf courses,
  boat ramps/marinas, fishing access, hardware stores, campgrounds, bar
  games (bowling/pool/fraternal clubs as a proxy for darts culture), pro
  sports distance, casino distance
- One exclusion zone: avoid a radius around any address (yes, including
  "my ex's apartment" — it just geocodes whatever you type)
- Click any hex for its full metric breakdown, no summarizing
- A monthly GitHub Action that re-pulls the data and redeploys

**BBQ is intentionally not a category** — see the original design notes;
grilling happens at home, not at a destination, so there's no clean POI
proxy for it in V1.

## Running it locally

This is a static site. No build step.

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

It ships with **synthetic sample data** (`data/hexes.geojson`, generated by
`etl/generate_sample_data.py`) so the map works immediately. The counts are
made up — replace them with real data before you trust the map for
anything. See `etl/README.md` for the real pipeline.

## Deploying to GitHub Pages

1. Push this repo to GitHub.
2. Settings → Pages → Source: **GitHub Actions**.
3. The included workflow (`.github/workflows/build-data.yml`) will build
   and deploy on push, and re-run the data pipeline monthly (1st of the
   month, 06:00 UTC). It also overwrites `data/raw/*.geojson` and
   `data/hexes.geojson` in place each run and removes any raw file that no
   longer matches a known category — nothing accumulates.
   **GitHub disables scheduled workflows after 60 days with no repository
   activity.** If you're not pushing commits regularly, either push
   something occasionally or open the Actions tab and click "Run workflow"
   on `build-data.yml` by hand every so often to keep the schedule alive.
4. If you'd rather deploy without the live data pipeline (i.e. keep the
   synthetic sample data, or run the pipeline locally and commit the
   output), just enable Pages with source **Deploy from a branch** instead
   and skip the workflow.

## Project structure

```
index.html            page shell
css/style.css          styling
js/app.js              map + filters + everything client-side
data/hexes.geojson      the data the site loads (synthetic by default)
etl/                     the real data pipeline — see etl/README.md
  generate_sample_data.py   makes the synthetic demo data
  fetch_osm_pois.py         pulls real POIs from OpenStreetMap (Overpass)
  build_h3_grid.py          builds the national hex grid
  compute_metrics.py        aggregates POIs onto the grid
  venues.py                 curated major-league sports venue list
  pipeline.py                runs the above three in order
.github/workflows/build-data.yml   monthly refresh + deploy
```

## Design notes

Styled like a government GIS portal / survey form, on purpose — the
contrast between "Form GS-1, Rev. 2026" seriousness and a slider labeled
"Avoid area around an address (or just 'My Ex's' old apartment)" is the
joke. No cartoon beer mugs.

## Known V1 limitations (see etl/README.md for detail)

- Counts are **per-hex**, not **per-radius** — the sliders say "at least N
  bars" but that's N bars inside that map cell, not within X miles of any
  point. Use a finer H3 resolution to approximate a tighter area.
- State/county/polygon exclusion are stubbed in the UI but not wired up —
  they need a boundary layer the pipeline doesn't produce yet.
- Sports/casino venues: `etl/venues.py` now ships with all 124 major-league
  venues (NFL/NBA/MLB/NHL) filled in. Casinos still come from OpenStreetMap
  automatically, same as the other categories. Worth a periodic
  double-check — see the note at the top of `venues.py` for a few
  franchises mid-relocation as of this writing.
- The Overpass fetch step needs real internet access at build time; it
  won't run in a network-restricted CI runner without allowing
  `overpass-api.de`.
